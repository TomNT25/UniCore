Version: 1.0.0
Date: 2026-09-24
Pipeline: Buffalo_L + Cosine Similarity + Liveness

1. Nguyên tắc thiết kế & Giới hạn bảo mật (Security Boundaries)

Tài liệu này định nghĩa giao thức kết nối chi tiết (API Contract) cho luồng Đăng ký khuôn mặt (Face Enroll) và Đăng nhập bằng khuôn mặt (Face Login).

Quy tắc bảo mật bắt buộc:
  • Không tin tưởng dữ liệu từ Client: Ở luồng Enroll, Backend lấy user_id từ Access Token đã xác thực. Client không được phép tự truyền user_id qua form-data.
  • Không truyền danh tính ở luồng Login: Ở luồng Login, Client chỉ gửi ảnh sinh trắc học. AI Engine tự thực hiện Similarity Search để suy ra Candidate user_id.
  • Xác thực hai yếu tố (2FA / Secondary Factor): Việc khớp sinh trắc học chỉ đóng vai trò yếu tố thứ nhất. Sau khi Face Match thành công, Backend yêu cầu người dùng xác nhận yếu tố thứ 2 (Mật khẩu phụ / PIN 6 số) trước khi cấp Session/Token.

2. Cấu trúc Phản hồi Chuẩn (Base Response Envelope)

Toàn bộ API thuộc module bắt buộc đóng gói phản hồi theo cấu trúc Envelope dưới đây:

2.1. Cấu trúc Response Thành công (Success)

{
  "isSuccess": true,
  "statusCode": 0,
  "message": "Xử lý thành công.",
  "data": { ... },
  "errors": [],
  "timestamp": "2026-09-24T03:00:00.000Z"
}

2.2. Cấu trúc Response Lỗi (Error)

{
  "isSuccess": false,
  "statusCode": 422,
  "message": "Kiểm tra chất lượng ảnh thất bại.",
  "data": null,
  "errors": [
    {
      "code": "MULTIPLE_FACES",
      "detail": "Phát hiện nhiều hơn 1 khuôn mặt trong khung hình."
    }
  ],
  "timestamp": "2026-09-24T03:00:00.000Z"
}

Mô tả chi tiết các trường Envelope

Trường (Field) Kiểu dữ liệu Bắt buộc Mô tả
isSuccess boolean Yes true nếu request xử lý thành công, false nếu xảy ra lỗi.
statusCode integer Yes 0 khi thành công. Khi thất bại, mã này phản ánh HTTP Status Code hoặc Mã lỗi nghiệp vụ.
message string Yes Thông điệp tổng quan mô tả kết quả xử lý.
data object | null Yes Payload chứa dữ liệu nghiệp vụ. Bằng null khi có lỗi.
errors array<object> Yes Mảng chứa thông tin chi tiết các lỗi (gồm code và detail). Mảng rỗng [] khi thành công.
timestamp string (ISO-8601) Yes Thời điểm tạo response theo định dạng UTC.

3. Chi tiết các Endpoint API

POST http://172.29.50.34:8001/face-recognition/enroll

Mục đích: Đăng ký hồ sơ sinh trắc học khuôn mặt cho người dùng đã đăng nhập. Hỗ trợ chế độ 1 ảnh hoặc 5 ảnh (các góc mặt khác nhau) để thực hiện Quality-Weighted Fusion.

Headers:

  • Authorization: Bearer <Access_Token> (Bắt buộc)
  • Content-Type: multipart/form-data

3.1. Request Body (multipart/form-data)

Tham số Kiểu dữ liệu Bắt buộc Mô tả
user_id String Yes User id requirement
username String Yes Username requirement
face_1 File (Binary) Yes Ảnh khuôn mặt chính diện (.jpg, .jpeg, .png, ≤ 10MB).
face_2 File (Binary) No Ảnh xoay trái (Multi-face mode).
face_3 File (Binary) No Ảnh xoay phải (Multi-face mode).
face_4 File (Binary) No Ảnh ngước lên (Multi-face mode).
face_5 File (Binary) No Ảnh cúi xuống (Multi-face mode).

3.2. Success Response (200 OK)

{
          "isSuccess": true,
          "statusCode": 0,
          "message": "Đăng ký khuôn mặt thành công.",
          "data": {
            items: {
              "user_id": "usr_9876543210",
              "username": "demo"
            }
          },
          "errors": [],
          "timestamp": "2026-09-24T03:00:00.000Z"
        }

3.3. Error Response Ví dụ (422 Unprocessable Entity - Liveness Fail)

{
          "isSuccess": false,
          "statusCode": 422,
          "message": "Kiểm tra Liveness thất bại.",
          "data": null,
          "errors": [
            {
              "code": "LIVENESS_FAILED",
              "detail": "Khuôn mặt trong ảnh không vượt qua kiểm tra chống giả mạo (Presentation Attack Detected)."
            }
          ],
          "timestamp": "2026-09-24T03:00:00.000Z"
        }
POST http://172.29.50.34:8001/face-recognition

Mục đích: Nhận diện danh tính người dùng qua ảnh khuôn mặt để bắt đầu luồng Đăng nhập (Login).

Headers:

  • Content-Type: multipart/form-data
  • X-Correlation-ID: <UUID> (Khuyến nghị dùng để trace request)

3.1. Request Body (multipart/form-data)

Tham số Kiểu dữ liệu Bắt buộc Mô tả
face File (Binary) Yes Ảnh chụp khuôn mặt để nhận diện (.jpg, .jpeg, .png, ≤ 10MB). Không truyền user_id/username.

3.2. Success Response (200 OK)

HTTP 200 OK - Tìm thấy danh tính khớp ngưỡng cấu hình

{
        "isSuccess": true,
        "statusCode": 0,
        "message": "Nhận diện khuôn mặt thành công.",
        "data": {
          items: {
              "user_id": "usr_9876543210",
              "username": "demo"
            }
        },
        "errors": [],
        "timestamp": "2026-09-24T03:00:00.000Z"
      }

3.3. Error Responses

HTTP 401 Unauthorized - Không có khuôn mặt nào khớp ngưỡng (NO_MATCH)

{
          "isSuccess": false,
          "statusCode": 401,
          "message": "Xác thực khuôn mặt thất bại.",
          "data": null,
          "errors": [
            {
              "code": "NO_MATCH",
              "detail": "Khuôn mặt không khớp với bất kỳ tài khoản nào trong hệ thống."
            }
          ],
          "timestamp": "2026-09-24T03:00:00.000Z"
        }

HTTP 422 Unprocessable Entity - Nhiều hơn 1 khuôn mặt trong ảnh

{
          "isSuccess": false,
          "statusCode": 422,
          "message": "Ảnh chụp không hợp lệ.",
          "data": null,
          "errors": [
            {
              "code": "MULTIPLE_FACES",
              "detail": "Phát hiện nhiều khuôn mặt. Vui lòng chỉ để một người trước camera."

          ],
          "timestamp": "2026-09-24T03:00:00.000Z"
        }

4. Bảng mã lỗi chuẩn hóa (Error Code Matrix)

Error Code HTTP Status Nguyên nhân / Ý nghĩa Hành động gợi ý cho UI/FE
INVALID_REQUEST 400 Bad Request Request thiếu trường bắt buộc hoặc sai định dạng payload. Hiển thị thông báo lỗi nhập liệu chung.
INVALID_TOKEN 401 Unauthorized Access Token bị hết hạn hoặc không hợp lệ (khi Enroll). Chuyển hướng người dùng về màn hình Đăng nhập lại.
NO_MATCH 401 Unauthorized Độ tương đồng Cosine < Ngưỡng cấu hình. Báo "Khuôn mặt không khớp. Vui lòng thử lại".
LOW_QUALITY 422 Unprocessable Entity Ảnh quá mờ, quá chói hoặc thiếu ánh sáng. Hiển thị hướng dẫn "Hãy chụp ở nơi đủ sáng và giữ yên máy".
NO_FACE 422 Unprocessable Entity Không tìm thấy khuôn mặt trong ảnh. Hiển thị hướng dẫn "Hãy đưa khuôn mặt vào giữa khung hình".
MULTIPLE_FACES 422 Unprocessable Entity Phát hiện > 1 khuôn mặt trong khung hình. Hiển thị hướng dẫn "Đảm bảo chỉ có 1 người trong camera".
LIVENESS_FAILED 422 Unprocessable Entity Không đạt kiểm tra liveness (ảnh giả/video/màn hình). Thông báo "Cảnh báo bảo mật: Xác thực không hợp lệ".
TOO_MANY_ATTEMPTS 429 Too Many Requests Vượt quá số lần thử đăng nhập/enroll cho phép. Khóa tính năng tạm thời và hiển thị đếm ngược thời gian thử lại.
MODEL_UNAVAILABLE 503 Service Unavailable Model AI / GPU server đang quá tải hoặc khởi động lại. Báo "Hệ thống bận, vui lòng thử lại sau giây lát".
INTERNAL_AI_ERROR 500 Internal Server Error Lỗi không xác định tại AI Processing Engine. Báo lỗi hệ thống chung.

5. Trách nhiệm xử lý giữa các thành phần hệ thống

Sơ đồ phân định trách nhiệm (Responsibility Separation):
Thành phần Nhiệm vụ bắt buộc Hành vi bị CẤM
Frontend (UI/App)
  • Chụp/Validate ảnh đủ định dạng, dung lượng ≤ 10MB trước khi gửi.
  • Hiển thị khung hình Hướng dẫn (Overlay Frame) để hỗ trợ căn chỉnh góc mặt.
  • Chỉ cho phép Face Login khi account có trạng thái FACE_ENROLLED.
  • Không gửi user_id hay username ở API Face Recognition/Login.
  • Không tự đưa ra quyết định xác thực nếu không có Session Ticket hợp lệ.
Backend API Gateway
  • Xác thực JWT Token đối với API Enroll; tự chèn user_id vào internal payload.
  • Quản lý Rate-limiting (Chống brute-force attack).
  • Lưu vết Audit Log (Request ID, Timestamp, Score, Status Code) không chứa raw image.
  • Không lưu trữ trực tiếp ảnh sinh trắc học gốc (Raw Image) trong cơ sở dữ liệu ứng dụng.
  • Không cấp Access Token khi chưa qua xác thực yếu tố thứ 2 (Secondary PIN).
AI Service (FastAPI)
  • Thực thi pipeline: Quality Check → Face Detection → Liveness → Embedding (Buffalo_L) → Search/Fusion.
  • Trả về lỗi có cấu trúc chuẩn Base Envelope khi vi phạm ngưỡng chất lượng.
  • Không tự quản lý trạng thái tài khoản hay quyền truy cập người dùng.
