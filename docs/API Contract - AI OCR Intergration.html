1. Tổng quan Luồng Nghiệp vụ (Workflow & Architecture)

Tài liệu này định nghĩa API Contract cho dịch vụ trích xuất thông tin Căn cước công dân (CCCD) Việt Nam bằng công nghệ OCR (VietOCR).

  • UI: Bắt buộc người dùng đặt ảnh CCCD nằm hoàn toàn trong khung (frame) quy định để khớp với hệ tọa độ bounding box cố định.
  • BE Gateway: Tiếp nhận file từ UI (kèm JWT Token), xác thực phân quyền, sau đó chuyển tiếp payload (gồm user-id và image) sang AI_OCR_API.
  • AI_OCR_API: Đánh giá chất lượng ảnh (độ chói, độ mờ, góc xoay), thực thi VietOCR để trích xuất văn bản và đóng gói kết quả theo Base Response chuẩn.
Quy tắc Hiệp đồng BE - FE:
  • Tất cả các API Response bắt buộc tuân thủ đúng cấu trúc Base Response Envelope.
  • Trường statusCode = 0 đại diện cho xử lý OCR thành công. Khi gặp lỗi, statusCode phản ánh mã lỗi HTTP hoặc mã lỗi nghiệp vụ tương ứng.
  • Trường errors là danh sách mảng chứa chi tiết lý do thất bại. Nếu thành công, errors là mảng rỗng [].

2. Cấu trúc Base Response Standard Envelope

2.1. Cấu trúc Response Thành công (Success)

{
  "isSuccess": true,
  "statusCode": 0,
  "message": "Trích xuất thông tin CCCD thành công.",
  "data": {
    items: {
      "id_number": "012345678901",
      "full_name": "NGUYỄN VĂN A",
      "date_of_birth": "01/01/1990",
      "sex": "Nam",
      "nationality": "Việt Nam",
      "place_of_origin": "Hà Nội",
      "place_of_residence": "Hà Nội",
      "date_of_expiry": "01/01/2030"
    }
  },
  "errors": [],
  "timestamp": "2026-09-24T02:48:56.920Z"
}

2.2. Cấu trúc Response Lỗi (Error)

{
  "isSuccess": false,
  "statusCode": 400,
  "message": "Ảnh không đạt yêu cầu chất lượng",
  "data": null,
  "errors": [
    "IMAGE_QUALITY_REJECTED: Độ chói hoặc độ mờ vượt quá ngưỡng cho phép, vui lòng chụp lại."
  ],
  "timestamp": "2026-09-24T02:48:56.920Z"
}

Mô tả Chi tiết các Trường Base Response

Trường (Field) Kiểu dữ liệu (Type) Bắt buộc Mô tả chi tiết
isSuccess boolean Yes true khi OCR và xử lý thành công, false khi xảy ra lỗi.
statusCode integer Yes 0 biểu thị xử lý thành công. Khác 0 (hoặc HTTP Status) khi có lỗi.
message string Yes Thông điệp tóm tắt kết quả xử lý.
data object | null Yes Object chứa kết quả OCR dữ liệu CCCD. Bằng null nếu xử lý thất bại.
errors array<string> Yes Mảng danh sách các thông báo lỗi chi tiết. Mảng rỗng [] khi thành công.
timestamp string (DateTime) Yes Thời gian phản hồi định dạng ISO-8601 (UTC).

3. Chi tiết API Endpoint

POST http://172.29.50.34:8000/ocr

Mục đích: Tải lên ảnh CCCD để hệ thống OCR trích xuất thông tin cá nhân.

Headers yêu cầu:

  • Authorization: Bearer <User_JWT_Token>
  • Content-Type: multipart/form-data

3.1. Request Body (Form-Data)

Tham số (Field) Kiểu dữ liệu Bắt buộc Mô tả
image File (Binary) Yes File ảnh CCCD chụp trực tiếp từ UI. Định dạng hỗ trợ: .png, .jpeg, .jpg. Dung lượng ≤ 10MB.

3.2. Response Data Schema (Trường dữ liệu trong data)

Trường (Field) Kiểu dữ liệu Ví dụ Mô tả
id_number string "012345678901" Số CCCD (12 chữ số).
full_name string "NGUYỄN VĂN A" Họ và tên in hoa trên thẻ.
date_of_birth string (date) "01/01/1990" Ngày sinh (Định dạng DD/MM/YYYY).
sex string "Nam" / "Nữ" Giới tính.
nationality string "Việt Nam" Quốc tịch.
place_of_origin string "Hà Nội" Quê quán.
place_of_residence string "Hà Nội" Nơi thường trú.
date_of_expiry string (date) "01/01/2030" Ngày hết hạn thẻ (Định dạng DD/MM/YYYY).

4. Hướng dẫn Tích hợp & Hiệp đồng (Integration Guidelines)

Lưu ý quan trọng về Bounding Box cố định: Do VietOCR trích xuất dựa trên khung định sẵn, UI bắt buộc phải cung cấp giao diện camera/upload có khung cố định (Overlay Frame) để hướng dẫn người dùng đặt vừa khít mặt trước CCCD.
Thành phần Trách nhiệm xử lý
Frontend (FE)
  • Kiểm tra định dạng file (PNG/JPEG/JPG) và kích thước file (≤ 10MB) trước khi gửi.
  • Sử dụng FormData để gắn trường image gửi tới API BE.
  • Nếu isSuccess === true, tự động điền (auto-fill) dữ liệu từ data vào form thông tin cá nhân.
  • Nếu isSuccess === false, đọc mảng errors[] để hiển thị thông báo hướng dẫn người dùng chụp lại ảnh (ví dụ: "Ảnh bị mờ", "Vui lòng đặt vừa khung").
Backend (BE Gateway)
  • Xác thực JWT Token từ Header.
  • Bổ sung user-id vào payload multipart và forward request sang AI_OCR_API.
  • Nhận kết quả từ AI Service và đóng gói chuẩn hóa theo đúng cấu trúc Base Response trước khi trả về FE.
AI OCR Service
  • Sử dụng FastAPI Middleware để bắt toàn bộ Exception về độ mờ, độ chói, độ xoay của ảnh.
  • Trả về lỗi có định dạng rõ ràng để BE Gateway dễ dàng mapping.
