Frontend ↔ Backend API Contract · Role = Admin

Create Student Account(s)

Đặc tả hai API dành cho admin để tạo tài khoản student: tạo đơn lẻ (single) và tạo hàng loạt từ file CSV (bulk). Hệ thống không cho student tự đăng ký; thông tin đăng nhập (username + password tạm) sẽ được BE gửi tới email đã đăng ký của nhà trường. Contract bao gồm request, success response, error response và toàn bộ enum quan trọng.

Base URL: /api/v1/admin

1. Mục tiêu và phạm vi

Module cho phép admin tạo tài khoản student theo 2 chế độ: nhập tay một tài khoản, hoặc upload file CSV để tạo hàng loạt. Với mỗi tài khoản, BE sẽ kiểm tra trùng lặp, sinh mật khẩu ngẫu nhiên, insert vào users, gửi email chứa username + password, và cập nhật whitelisted_emails nếu gửi mail thành công.

{
  "isSuccess": false,
  "statusCode": 409,
  "message": "Duplicate student code",

Nguyên tắc: FE rẽ nhánh theo isSuccess; không dùng HTTP status code cho logic nghiệp vụ. HTTP status code vẫn phải đúng để tương thích hạ tầng.
Trường errors: luôn là mảng. Khi thành công là [], khi lỗi chứa message chi tiết. Không trả null.

8. CSV Format Specification

File CSV phải tuân theo format dưới đây. BE validate header trước khi xử lý; nếu header sai → reject cả request với 400.

8.1. Header

CộtBắt buộcMô tả
student_codeCóMã student, unique toàn hệ thống.
emailCóEmail đã đăng ký với nhà trường, unique toàn hệ thống.
Thứ tự cột: BE không bắt buộc đúng thứ tự, chỉ cần header đúng tên. Tuy nhiên để tránh nhầm lẫn, document khuyến nghị giữ đúng thứ tự như trong mục 8.2.

8.2. Ví dụ file hợp lệ

student_code,email
ST2024001,student1@example.com
ST2024002,student2@example.com
ST2024003,student3@example.com

8.3. Ví dụ file có row lỗi

Row lỗi không làm hỏng cả file; BE xử lý các row còn lại và tổng hợp vào error_accounts.

student_code,email
ST2024001,student1@example.com
ST2024001,duplicate-code@example.com
ST2024003,student1@example.com
ST2024004,student4@example.com
  • Row 2: trùng student_code với row 1 → error_type: STUDENT_CODE.
  • Row 3: trùng email với row 1 → error_type: EMAIL.

9. Business Workflow

9.1. Per-account workflow

Đây là flow áp dụng cho từng row, dùng chung cho cả single và csv.

1
Validate inputKiểm tra student_code và email không rỗng, đúng định dạng.
2
Check duplicateQuery users theo student_code và email.
3
Generate passwordSinh random_password (chỉ giữ trong RAM).
4
INSERT userGhi users với is_active=false, provider="SYSTEM", created_by=admin.id.
5
Send email + update whitelistGửi mail credentials. Thành công → set whitelisted_emails.student_id.

9.2. Xử lý kết quả từng row

Kết quảĐiều kiệnGhi vào
SuccessDuplicate check pass + INSERT thành công + gửi mail thành công + update whitelist thành công.success_accounts
Duplicate student_codeQuery thấy users.student_code đã tồn tại.error_accounts với error_type: "STUDENT_CODE"
Duplicate emailQuery thấy users.email đã tồn tại.error_accounts với error_type: "EMAIL"
Send email failedINSERT thành công nhưng mail provider báo lỗi/timeout.error_accounts với error_type: "SENT_EMAIL_FAILED"

9.3. Transaction boundary

Cần chốt ở Open Points: mỗi row được xử lý trong transaction riêng hay toàn bộ file trong một transaction?
  • Per-row transaction (khuyến nghị): row lỗi không rollback row khác; partial success tự nhiên.
  • Single transaction: nếu 1 row lỗi thì rollback tất cả — nhưng khi đó error_accounts không còn ý nghĩa, phải trả về lỗi cấp request.

9.4. Sequence — student accounts

Admin UI

  ├─ POST /api/v1/admin/student-accounts (multipart)
  │        │
  │        ▼
  │   BE parse CSV → validate header
  │        │

  │        │     ├─ check duplicate
  │        │     ├─ generate password
  │        │     ├─ INSERT users
  │        │     ├─ send email
  │        │     ├─ (success) update whitelisted_emails.student_id

12. Acceptance Criteria

IDRequirement
STU-01POST single tạo user trong users với username = student_code, provider = "SYSTEM", is_active = false, is_email_verified = false, last_login_at = null, failed_login_attempts = 0, lockout_end = null, created_by = admin.id.
STU-02password_hash là hash của password ngẫu nhiên sinh tại BE; password gốc không bao giờ xuất hiện trong response hay log.
STU-03BE gửi email credentials tới email trong request. Thành công → set whitelisted_emails.student_id.
STU-04Single duplicate student_code → 409 với message = "Duplicate student code".
STU-05Single duplicate email → 409 với message = "Duplicate email".
STU-06Bulk CSV validate header student_code, email trước khi xử lý; header sai → 400 Invalid CSV format.
STU-07Bulk xử lý theo per-row; row lỗi không làm hỏng row khác; kết quả tổng hợp trong data.items.
STU-08error_type chỉ nhận một trong "EMAIL" | "STUDENT_CODE" | "SENT_EMAIL_FAILED".
STU-09error_accounts[].id là null khi row bị reject trước insert (duplicate), là uuid khi insert thành công nhưng gửi mail thất bại.
STU-10Response tuân theo envelope: isSuccess, statusCode, message, data, errors, timestamp.
STU-11Success trả statusCode = 0; error trả statusCode bằng HTTP status code.
STU-12errors luôn là mảng; data là null khi lỗi.
STU-13Không tạo user_profiles hay user_mfa_settings trong flow này.
STU-14Cả hai endpoint yêu cầu role admin.
